# Trend sleeve invariants (HIGH severity if violated)

Moved verbatim from `CLAUDE.md` §Ticks, streams and signals. Loads when the
files above are touched.

- **The trend sleeve is daily-bandwidth only and off unless evidence enables it** — an enabled sleeve (`HYDRA_TREND_SLEEVE=1`, or `auto` with a passing gate, below) replaces the 1h signal generator and hold-through rails with `Strategy.TREND`: long while the ensemble on COMPLETED daily closes (`sleeve_trend_score`, never the forming day) is ≥0.6, flat otherwise. A held sleeve re-sizes every `SLEEVE_RESIZE_DAYS` (30) to `equity × max_position_pct × _sleeve_vol_multiplier()` unless already within `SLEEVE_RESIZE_TOL` (10%) — never re-sized, a rally drifted it to ~0.9 of equity (58% drawdown and a breaker trip in year one, vs 14.3% re-sized — K3b post-hoc, `research/data/abi/`). That trim is the engine's ONLY partial SELL; every other SELL is a full close. `TREND_SLEEVE:exit` and `TREND_SLEEVE:trim` are protected (rules, LLM, coordinator and a zero multiplier keep them). Entries and top-ups stay subject to the breakers, the portfolio BUY halt, `exit_only`/`tradable`, the confidence floor and, in triangle mode, the coordinator — but **sleeve pairs skip Phase 2 entirely** (`HydraAgent._route_phase2`): no LLM and no R1–R11/QFE on any sleeve signal, under `=1` too, because the gate tested the deterministic sleeve and a veto layer outside the test would make live trading differ from the evidence. Breakers, caps, post-only, repricing and the one-resting-order rule still apply; the brain-free-guardrail invariant governs 1h-engine pairs. `execute_signal` admits a BUY only when the sleeve wants long and is flat or owes a due top-up, refuses a non-protected SELL while it wants long (a 1h exit would re-couple it to the rejected exits), and always passes the halt flatten. The re-size clock `_sleeve_sized_day` rides in `snapshot_position` (a cancelled trim is owed again; fill appliers re-stamp it on a real fill; a PARTIAL fill restores the pre-trade clock via `reconcile_partial_fill`). Top-ups and trims skip the entry friction gate and the API-cost haircut. **Who runs it is decided per pair by evidence** (`hydra_strategy_gate.resolve_trend_sleeve`): unset/`auto` enables a stable-quoted pair only when `research/data/trend_sleeve_gate.json` (or `HYDRA_TREND_SLEEVE_GATE`) is a `tools/trend_sleeve_gate.py --engine` report with verdict PASS **and** `significant`, built for the engine's current re-size rules, long threshold, competition cap and vol target (`trend_target_vol_setting`), whose run and last tested data day are younger than `HYDRA_TREND_SLEEVE_GATE_MAX_AGE_DAYS` (180), with a PASS and engine check on every stable-quoted entry of that base. Anything else, including a missing or malformed file (numbers must be finite non-bool JSON), leaves the pair on the 1h engine. `1`/`0` override; any other value is OFF with a reason, never `auto`. The report is gitignored, and `tests/conftest.py` plus the live harness pin tests away from an operator's report (with a PASS present, every test agent would run the sleeve and skip the brain-free guardrail path). **Never commit a gate report** built on data other than the operator's store — it would switch production. Boot prints one `[STRATEGY]` line per pair; the dashboard gets `strategy_gate`. The engine publishes `trend_sleeve.plan` (the daily close that flips the decision, each term's level, the breaker price), closed-form and tested against its own next-close decision (`docs/TRADE_PLAN.md`; registration `research/data/trend_sleeve_REGISTRATION.md`, amendment A1; null-calibrated, `research/data/trend_sleeve_gate_calibration.json`).
