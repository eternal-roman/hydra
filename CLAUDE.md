## Operating Rules (binding, non-negotiable)

Each was earned by a documented past failure; breaking one is a regression bug, not a style issue.

1. **Partition big audits instead of skimming them** — for a full-repo review, run `/audit` (it owns the partitioning and its parallel agents). For a narrower review over ~20 files, split it into 3–4 partitions (parallel agents optional), each returning HIGH/MED/LOW, then synthesize; below that, review it directly.
2. **Stop processes before editing their state** — a live writer overwrites your edit on its next tick. Find the owner in `docs/STATE_FILES.md`; stop it, edit, verify the edit persisted, restart. Snapshot + journal must stay in sync — clean both together.
3. **Verify claims with actual commands** — "verified", "passing", "fixed" require running the check (`pytest`, `git tag -v`, …) in the same turn and pasting the output.
4. **Self-audit new code — twice where money moves** — after writing, check for unused imports, dead code, unhandled exceptions, null/empty crashes, deprecated APIs, misleading errors and false-positive checks, and fix them. Execution-path and money-handling code (`hydra_engine.py`, `hydra_agent.py`, `hydra_quant_rules.py`, `hydra_streams.py`, `hydra_kraken_cli.py`, sizing/journal/balance logic) gets a second pass before declaring done; tests, tools, research, docs and dashboard code need one.
5. **Enumerate every version site before a bump** — run `git grep -nE 'v?[0-9]+\.[0-9]+\.[0-9]+'`, confirm each entry in §Version sites, and update all of them in one commit.

## Project

- **HYDRA** — regime-adaptive crypto trading agent for Kraken: detects trending/ranging/volatile regimes, switches among 4 strategies (Momentum, MeanReversion, Grid, Defensive), executes limit post-only.
- **Product thesis (evidence-locked — don't overclaim):** the live path is **capital preservation** (hold-through + daily trend overlay + friction + 15% BUY-only breaker), not proven growth alpha. The only after-fee selection edge is **S3 daily bounce X1 on BTC/ETH** — shadow-only (`HYDRA_S3_STRATEGY`, no order path) and not significant (BTC t=0.74, ETH t=1.59). **Heartbeat** (BTC/ETH order-flow P(up)) is display + shadow co-log + brain advisory, **never** a live BUY/SELL gate. Its 2026-07 PASS was scored with a labeler leak and is withdrawn: the 2026-10-02 leak-fixed walk-forward gives tier-0 bounce+3 means of BTC 0.38, ETH 0.63, SOL 0.42, ZEC 0.38 (two folds of 7–11 events) against a 0.70 bar (`research/data/abi/heartbeat_leakfix_2026-10-02.json`). SOL/ZEC flow FAIL; ZEC S3 untradable. The only candidate with a risk rationale is the daily trend sleeve (`HYDRA_TREND_SLEEVE`, default `auto`): a pair trades it only after its pre-registered gate passes, significantly, on the operator's own data (`hydra_strategy_gate`, `run_strategy_gate.bat`); otherwise it stays on the 1h engine. Plan and session routine: `docs/TRADE_PLAN.md`. Ledger: `heartbeat/HONEST_FINDINGS.md`; funnels: `heartbeat/evidence/ABI_FUNNEL_2026-07-19.md`, `research/ABI_FUNNEL_2026-10-01.md`.
- **Pairs (default):** BTC/USD, ETH/USD, ZEC/USD — three independent stable-quoted cores; no triangle or coordinator (both `_derive_triangle`s return None; the coordinator is a no-op). The SOL triangle was dropped (no SOL edge on 90d real tape — `heartbeat/evidence/real_tape/calibrate_SOL_USD.txt`, AUC 0.56 FAIL; the bridge was already dead), but `--pairs SOL/USD,SOL/BTC,BTC/USD` still re-activates TradingTriangle + CrossPairCoordinator unchanged. `STABLE_QUOTES = {USD, USDC, USDT}` are first-class.
- **`--pairs auto`** (`hydra_agent.discover_portfolio_pairs`) seeds the three cores in the *funded* stable quote — `--quote` / `HYDRA_QUOTE` when that pool is above costmin, else the largest funded stable (a USDC-only book must not run USD cores at $0 cash) — plus one satellite per other held asset (held SOL becomes an ordinary satellite, USDC-quoted when USDC is funded, else USD; `HYDRA_AUTO_QUOTE` forces).
- **Bridge is signal-only by default:** with an explicit SOL triangle, the SOL/BTC engines run `exit_only` drain (zero trades in 1y and a Sharpe drag on real 1h tape — `.hydra-flywheel/bridge_isolation.json`); `HYDRA_BRIDGE_TRADING=1` opts back in.
- **Candles default 60m:** the hold-through rails and friction hurdle are calibrated on 1h tape. `--candle-interval` accepts 1/5/15/30/60; resume drops candle history on an interval mismatch (positions and journal still restore). `--resume` remaps same-base stable keys (BTC/USD snapshot → BTC/USDC engine) even with no triangle; mixed leftover quotes (ZEC/USD) stay exact — never a global quote flip that invents ZEC/USDC.

## Cross-cutting invariants (HIGH severity if violated)

**Execution scope**
- **SPOT-ONLY execution** — orders go only to Kraken spot pairs. Derivatives data (funding/OI via `kraken futures tickers`) is SIGNAL INPUT ONLY: no futures, options or margin orders. `hydra_derivatives_stream.py` is read-only by construction; its tests grep for authenticated subcommands.
- **Limit post-only, never market** (`--type limit --oflags post`; deliberate). **2s REST floor** between calls (Kraken throttles or bans below it). **No REST for market data** — WS streams or the `kraken` CLI only, including for new sources.
- **Research surfaces never place orders** — `hydra_s3`/`s3bounce` and `hydra_heartbeat_surface`/`heartbeat` are signal, display, shadow or brain-advisory only (test grep-guards forbid order verbs). No `HYDRA_S3_LIVE` or heartbeat-driven engine SKIP without a powered, pre-registered bakeoff (engine co-occurrence currently FORBIDs it: 0 BUYs / 365d under rails).
- **`HYDRA_COMPANION_LIVE_EXECUTION` default OFF** — companion proposals stay paper until opted in (`HYDRA_COMPANION_LIVE_EXECUTION=1`); confirm it is unset before live debugging. Opted-in companion orders register on `ExecutionStream` but stay engine-inventory-blind until a full agent place adapter exists.
- **Paper never touches live state** — paper/demo persist snapshot, journal, backfill and tuner params under `.hydra-paper/` (`state_dir_for_mode`); the companion launcher runs `--paper` from the production directory. Live `--resume` refuses a snapshot whose `paper` flag differs; the journal merge drops rows whose `intent.paper` differs (`journal_row_matches_mode`; flagless legacy rows count as live).

**Circuit breaker and exits**
- **15% drawdown sticky-halts new BUYs (engine and portfolio); SELL flatten is always allowed when `position.size > 0`** (PR-A) — both `tick()` and `_maybe_execute` check. It arms on CURRENT drawdown (`hydra_engine.tick`: `drawdown`; `hydra_agent._note_portfolio_equity`: `cur_dd`), never on the monotone `self.max_drawdown` record — arming on that re-halted the engine on the tick after a reset. At resume the portfolio halt restores from its own saved flag (`portfolio_drawdown.buy_halted`), never re-derived from `max_pct`. The portfolio flag arms before Phase 2.5, not after the order is sent.
- **The halt survives `--resume`** (`halted` restores from the snapshot; boot prints RESUMED-STILL-HALTED) and is cleared only by the operator via `HYDRA_RESET_CIRCUIT_BREAKER=1`, which starts a new drawdown epoch (v2.34.5): it clears the flag and moves the peak to the equity at the first tick after it (`max_drawdown` stays as the record), and the breaker re-arms on a further 15% from there. Keeping the old peak made the reset a no-op after every real breach (the halt flattens the book, and the cash left sits 15% under that peak and can't recover). A pre-reset position snapshot (`peak_epoch`) never restores the old peak on rollback. The env var acts on EVERY start while set — unset it after the start that cleared the halt. Never auto-clear on resume.
- **Breakers measure trading losses on Hydra's own books; moving capital is not a loss (v2.34.5)** — the portfolio breaker reads `_books_equity_usd` (engine quote cash plus engine-held positions, the backtest's sum), not the Kraken account total, which counted coins no engine held and every deposit or withdrawal, and so blocked every BUY for good. Every non-fill write of engine cash (`_set_engine_balances` at boot, `_refresh_tradable_flags`) goes through `_reseed_engine_cash`, which rescales the engine peak so the drawdown FRACTION is unchanged; the portfolio peak rescales by the same net flow (`_rebase_portfolio_peak_for_flow`). A seed/resume never erases or creates a drawdown, and a book seeded to nothing has no peak; a new cash-seeding path must use the helper. An unpriced held position makes the books unknown for that tick (skip, never value at zero). A snapshot without `portfolio_drawdown.basis` holds a whole-account peak: it is dropped, and a breach it recorded stays halted until the operator reset.
- **Entry controls never gate exits** (PR-A) — `tradable=False` (derived from the QUOTE balance, which a SELL doesn't spend) blocks entries only; gating exits on it stranded inventory. SELL ignores `min_confidence`. R2 force-holds extreme-negative-funding BUYs, never a spot SELL. R1–R11 never rewrite a halt flatten or hold-through flatten to HOLD, and `execute_signal` never turns a `[QUANT RULES FORCE_HOLD]` back into a sell.
- **`exit_only` drain mode** — engine flag: BUYs refused (SKIP semantics), every SELL path untouched; set per session by the agent, never persisted; the bridge default uses it; composes with hold-through and the breaker.
- **SKIP ≠ BLOCK** — a soft restriction skips an action for the tick; BLOCK is reserved for hard rules (the 15% breaker).

**Guardrails and the LLM**
- **Deterministic guardrails never depend on the LLM layer** — `HydraAgent._apply_quant_guardrails` runs R1–R11 + QFE for any actionable signal when `self.brain` is None (they used to run only inside `_apply_brain`) (positioning_bias `""`, so R8 can't fire); boot prints which layer is live. Making the rules brain-conditional again is a HIGH regression. A brain call that outlasts the tick wait is abandoned: the tick trades the pre-brain snapshot plus these rules, and the late return must not write the replay cache or mark the candle evaluated.
- **The LLM may veto or exit, never open** — fresh and cached-replay verdicts both go through `merge_llm_verdict(engine_action, final_signal)`: HOLD vetoes, BUY→SELL turns an entry into an exit, SELL→BUY becomes HOLD, and nothing comes from an engine HOLD. The cache is keyed by (candle, engine action), so a BUY after a SELL deliberation is deliberated fresh. A non-protected SELL sized 0 by the LLM is an explicit HOLD (QFE can still rescue a profitable exit); a SELL with no inventory skips the LLM. `HYDRA_QUANT_INDICATORS_DISABLED` removes the indicator rules, never the cached LLM veto. ADJUST appends to the engine reason (the ride-trend rail re-reads it). RM drawdown mandates read `current_drawdown_pct` (`max_drawdown_pct` is a record only); the breaker mandate blocks BUYs, never exits.
- **Nothing reachable from the brain's tool loop runs inline** — the dispatcher executes on the LIVE TICK THREAD; `run_backtest` and `sweep_param` route through `BacktestWorkerPool` when mounted (I1). A new long-running handler must too, or it stalls ticks, fill reconciliation and shutdown with positions open.
- **R11/QFE is exit-only, profit-only, squeeze-filtered** — `evaluate_qfe()` (`hydra_quant_rules.py`) lets a SELL through force_hold only when the position is in profit by ≥`QFE_MIN_PROFIT_PCT` (1.0% mark, fee-cushioned), the engine already generated SELL, and no **deterministic** squeeze catalyst is present (`short_squeeze` OI regime, or extreme-short funding + accumulation CVD); LLM `positioning_bias=crowded_short` alone does not veto it. QFE never opens, never fires underwater, and force_hold stays active for entries afterwards. Every event logs `qfe_trigger_values` in `state["ai_decision"]`.
- **Quant/cross-pair (PR-E)** — `HYDRA_QUANT_INDICATORS_DISABLED=1` skips `apply_rules`/QFE (no R10 blackout). Rules re-apply after a brain OVERRIDE. Coordinator Rule 2 recovery is preferred over Rule 3 swap; Rule 3 needs bridge `tradable` (emitted from `_build_state`). Always `tick(generate_only=True)`, then execute post-coordination. USDT pairs are mapped in `SPOT_TO_DERIVATIVES`.
- **Derivatives coverage and funding math** — pairs declare derivatives coverage to R10 structurally (from `SPOT_TO_DERIVATIVES`, never from data presence), or R10 force-holds them every tick; a new pair without a direct perp needs the matching flag. Funding bps are markPrice-relative and hourly-scaled, never `fundingRate * 10000`. Full invariants: `.claude/rules/derivatives.md`.

**Sizing and balances**
- **Gross vs free balance are different numbers** — equity, peak equity and the drawdown breakers read GROSS (`BalanceStream.latest_balances()`, `_cached_balance`; includes funds held by our own resting orders). Every spendability decision reads FREE (`BalanceStream.latest_free_balances()`, `KrakenCLI.free_balance()` / `kraken extended-balance`) through the `_get_real_quote_balance` chokepoint — sizing on gross re-commits held money (the `PLACEMENT_FAILED: insufficient_<quote>_balance` loop). Fail OPEN to gross when the hold field is absent or the free read failed (error envelope, exception, missing payload); a successful read of free 0 (asset present at 0, or an empty map because every unit is on hold) is not spendable.
- **Per-quote balance pools** — live engines size from the REAL holding of their own quote, split across pairs sharing it (`_set_engine_balances`); a USDC engine never sizes against USD it can't spend. A zero pool ⇒ balance 0 (no entries) but `tradable` stays True so inventory can exit. Paper uses a uniform split. On resume, a book with `position.size > 0` or a `PLACED` row keeps its restored cash; flat engines with no working order seed from the free pool minus cash already on those books, but each flat book restored from the snapshot keeps its own cash (`_seed_cash`): a pool surplus is shared equally across the flat books, a shortfall shrinks every restored book by the same factor, and a pair new this session (`_snapshot_restored_pairs`) shares only the surplus. Paper keeps its restored books as they are. The old equal re-split moved banked gains between engines at every restart and left the winner under its own peak, so its breaker halted it.
- **De-risking multipliers survive every later sizing step** — a `size_multiplier` (brain quant × RM, or the R3/R5/R7 penalty stack) must reach the placed order: applied as a pass-through capped at 1.5 that never expands values above 1; non-finite or negative sends nothing. A SELL multiplier of 0 sends nothing unless the SELL is protected (`is_protected_flatten_reason`: halt flatten, hold-through flatten, trend-sleeve exit/trim); a partial sell penalty doesn't change a full close (`size_multiplier_applied: false`). Any floor/override after `size = size * effective_mult` in `_maybe_execute` must scale by `effective_mult` too, or it silently discards the risk stack. `max_position_pct` applies **after** `size_multiplier` and caps gross inventory (PR-B). The API-cost haircut scores the notional about to be sent, after the vol haircut and gross cap. Unknown bases are never sized or written off at a made-up 0.02 ordermin.
- **Kelly / friction honesty (PR-D)** — PositionSizer uses excess-over-threshold Kelly (conf=min → edge 0.10, conf=1 → 1.0), not `(conf*2-1)`. The friction hurdle is timeframe-aware (≥2.0% on 1h+ bars). Go-live plumbing gates: `python scripts/go_live_gates.py`.

**Orders, fills and the journal**
- **One resting order per pair** — a `PLACED` journal row blocks another `execute_signal` on that pair (a second order makes the first one's true-up restore an older snapshot and wipe or double the position). Same-side signals and an ordinary HOLD wait. An opposite signal cancels the resting order (paper/demo: restore `pre_trade_snapshot`, mark `CANCELLED_UNFILLED`; live: `cancel_order`, then the execution stream rolls the book back) and places nothing that tick. A resting BUY is also cancelled by an entry veto (rules HOLD, brain HOLD, API-down block, confidence floor) or the portfolio buy halt; a resting SELL is not cancelled by a HOLD. Fills and cancels rewrite rows in place, so snapshot whenever the book changes even if the journal didn't grow (else `--resume` reloads the pre-fill position). That cancel clears a breaker halt only when the unfilled buy itself armed it (pre-buy book under 15% at the current price; marked `halt_from_unfilled_buy` on the engine snapshot, and re-marked from the resting buy after `--resume` while still past 15%). A real breach stays sticky until `HYDRA_RESET_CIRCUIT_BREAKER=1`, even after the book recovers; a restored book at or past 15% stays halted.
- **An ambiguous placement is never `PLACEMENT_FAILED`** — after an error where Kraken may already hold the order (`transport_timeout`/`_empty`/`_exit`/`_parse`, upstream `network`/`parse`; `placement_outcome_unknown`), the row stays `PLACED` with `lifecycle.unconfirmed`, no txid and the engine's optimistic book; the stream tracks it as `userref:<n>` and adopts the txid from the first execution entry (rolling back let the next tick place a duplicate live order). It is declared not accepted only after `UNCONFIRMED_PLACEMENT_GRACE_S` with the execution stream connected and no restart since the send; a txid-less success (`accepted_without_txid`) or a row from an earlier process is never auto-rejected — it holds and warns. `PLACED` rows the stream can't finalize (boot query error, sequence gap, cancel answered "Unknown order") are re-queried in session (`_requery_stale_placed`); `_apply_execution_event` ignores a second terminal event for a row no longer `PLACED`.
- **A working order the market left behind is re-priced** — after `HYDRA_ORDER_REPRICE_S` (default 900) with the touch ≥`HYDRA_ORDER_REPRICE_BPS` (default 15) beyond the limit, `_reprice_stale_resting` cancels it and the engine re-decides at the current touch next tick, still limit post-only (fills book optimistically, so a parked exit read flat while the coins fell, blinding the breaker). This is the only case where a resting SELL is cancelled without an opposite signal.
- **Fill true-up (PR-C)** — every terminal FILLED/PARTIAL restores `pre_trade_snapshot` and replays at exchange `avg_fill_price` (not candle close). `pre_trade_snapshot` IS persisted (only `PLACEMENT_FAILED` entries are stripped), so `_reconcile_stale_placed` trues up a previous-session fill and rolls back a phantom position on CANCELLED/REJECTED exactly as `_apply_execution_event` does live. Unsellable dust below ordermin is written off. BUY limit offsets are capped (≤20 bps SOL/STABLE) for post-only fill rate.
- **`PLACEMENT_FAILED` entries are session-only** — pre-exchange diagnostics (`insufficient_USD_balance`, `placement_error:api`) live in the in-memory `HydraAgent.order_journal` and MUST NOT persist to `hydra_session_snapshot.json` or the rolling `hydra_order_journal.json`. `_journal_for_persistence()` is the single chokepoint for both write paths (`_save_snapshot`, the per-tick rolling write); route any new write path through it.
- **The journal cap never drops a working order** — `_trim_journal` removes session-only `PLACEMENT_FAILED` rows first, then the oldest terminal rows, never a `PLACED` row; a new working order sets `_books_dirty` so the snapshot is written even when the capped journal stops growing. A BalanceStream snapshot replaces both balance maps atomically (a merge kept assets sold to zero during an outage).
- **On shutdown the agent cancels all resting limit orders and flushes the snapshot** — do not bypass it.

**Ticks, streams and signals**
- **Every pair with a state lands in `all_states`** — it is Phase 2.5's sole input, so `all_states[pair] = state` sits OUTSIDE the brain / brain-free / cached-replay branches; nesting it in one arm drops the other arms' pairs (no entries and **no exits**) while ticks, logs and the dashboard look healthy.
- **Stream recovery runs in `finally`** — `ensure_healthy()` for the candle/ticker/balance/book streams sits in the tick body's `finally`, never the try body: gating it on tick success turns a dead stream into the same crash every tick, permanently, with no exits. `engine_states[pair]` is explicitly `None` for a skipped pair — use `.get(pair) or {}`; `.get(pair, {})` doesn't apply its default when the key exists.
- **Finished bars reach the engine in final form** — `CandleStream` keeps the previous interval's last push (`latest_closed_candle`) and `_fetch_and_tick` ingests it before the forming bar (otherwise a 300s tick froze closed bars and daily closes up to 5 min early). With no pushed candle (paper, or a dead live stream) the pair ticks from `kraken ohlc` instead of being skipped, so exits and halt flattens keep flowing during an outage. Declared, not fixed: live decides on the forming bar ~12×/bar; backtests decide once per closed bar.
- **Trend overlay is evidence-gated and fails open** — every `daily_trend_long()` consumer treats `None` (warmup/disabled) as "behave exactly as pre-overlay". Entering on the daily ensemble alone was tested and REJECTED (whipsawed against 1h flattens: −5.4% vs +0.1% over 2y, `.hydra-flywheel/trend_entry_gate.json`) — don't re-add it without a passing gate. Daily closes seed at boot (agent: Kraken 1440m OHLC; backtest: pre-window sqlite) and persist in the snapshot.
- **The trend sleeve is daily-bandwidth only and off unless evidence enables it** — full invariant: `.claude/rules/trend-sleeve.md`. Cross-cutting parts: sleeve pairs skip Phase 2 entirely (no LLM, no R1–R11/QFE — the brain-free-guardrail invariant governs 1h-engine pairs only); `TREND_SLEEVE:exit`/`:trim` are protected; **never commit a gate report** built on data other than the operator's store — it would switch production.
- **No blanket bar-count hold** (was PR-F's 50) — regime and signals use whatever history each indicator has: RSI is neutral until 15 closes, MACD zero until 26, a collapsed Bollinger band never counts as a touch, EMA trend can't classify until both averages exist.
- **RSI/ATR = Wilder exponential smoothing, NOT SMA**; Bollinger uses population variance.
- **`hydra_rm_features.py` is pure** — no I/O, subprocess, network or file access; every function returns `Optional[float]` (or `Optional[dict]`) from its inputs alone, `None` on insufficient data. That fail-silent contract lets R10 and RM tell missing data from corrupted data and makes `HYDRA_RM_FEATURES_DISABLED` an instant rollback.
- **Backtest/evidence invariants (path-scoped)** — timestamp-aligned backtest candles, null-calibrated evidence tooling and trade-level Sharpe annualization live in `.claude/rules/backtest-evidence.md`, loaded when backtest, metrics, walk-forward, flywheel, S3, `tools/`, `research/`, `heartbeat/` or `s3bounce/` files are touched. Read it before changing any evidence gate.

**Pairs, config and auth**
- **Pair identity has one source of truth** — `hydra_pair_registry.PairRegistry` owns alias resolution (XBT↔BTC, XZEC↔ZEC, ZUSD↔USD, USDC.F→USDC, slashed↔slashless, case-insensitive) and per-pair metadata (price decimals, ordermin, costmin, tick size); `hydra_kraken_cli.KrakenCLI` delegates to its class-level `registry`. Never re-implement an alias dict. CLI schema drift degrades to the registry, never to a literal: `load_pair_constants` loudly skips a pair with missing/unparseable `pair_decimals`/`ordermin`/`costmin` (a generic default once gave every pair `ordermin=0.02`, and `write_off_dust` erased sub-0.02 BTC positions); `KrakenCLI.balance()` skips unparseable entries instead of raising.
- **Roles, not literal pair names, in coordinator/agent logic** — CrossPairCoordinator and HydraAgent address pairs by `TradingTriangle` role (`stable_sol`, `stable_btc`, `bridge`), never a hardcoded `"SOL/USDC"`. The engine treats every `STABLE_QUOTES` member as $1; switching the default quote is a config flip (`hydra_config.HydraConfig.from_quote`), not a refactor.
- **The dashboard WS authenticates BOTH directions** — an unauthenticated socket receives nothing (no `latest_state`, no broadcast) and closes after `HYDRA_WS_AUTH_GRACE_S`; auth, not loopback binding, protects the account, and nothing is restored on connect behind `_origin_allowed`. Full invariant: `.claude/rules/dashboard-ws.md`.

## Launchers

- `start_hydra.bat` — production watchdog: `--pairs auto --mode competition --resume` (**do not remove these flags**); starts `start_heartbeat.bat` once before the restart loop only when `HYDRA_START_HEARTBEAT=1` (default off; idempotent if heartbeat.exe is already up).
- `start_all.bat` — dashboard + agent watchdog (heartbeat only via `HYDRA_START_HEARTBEAT=1`). `start_dashboard.bat` — dashboard only.
- `run_strategy_gate.bat` — refreshes `hydra_history.sqlite`, runs `tools/trend_sleeve_gate.py --engine`, prints the per-pair strategy `auto` will pick. No orders.
- `start_heartbeat.bat` — `heartbeat run` for BTC/USD + ETH/USD (research P(up) status files, **no order path**; USDC-quoted cores read the USD tape via `status_path_candidates`; ZEC is flow-FAIL and not started).
- `start_hydra_companion.bat` — paper-mode companion testing (no real money), same `--pairs auto` as production.

**A launcher's explicit `--pairs` overrides the code default and does not drift with it.** When the default pair set changes, re-check `start_hydra.bat` and `start_hydra_companion.bat` by hand — nothing else does, and no test covers `.bat` content (both once kept trading the rejected SOL triangle, with no ETH or ZEC, for several releases).

## Release, CI and audit

- **Cycle:** branch → tests pass → PR → CI green → merge → signed tag; the `/release` skill codifies it. **Never merge with red or pending CI.**
- **CI gates:** `watermark-gate` + `engine-tests` + `dashboard-build`. `watermark-gate` is a merge blocker: agent trailers (e.g. AI `Co-Authored-By:` lines), "Generated with" banners, or actionable invisible Unicode in files changed vs `main` (not Layer B).
- **Mock harness** (`tests/live_harness/harness.py --mode mock`) is **MANDATORY** for any PR touching the execution path (modes: smoke/mock/validate/live).
- **Tests:** `python -m pytest tests/` or individual `python tests/test_*.py` (the CI pattern).
- **Audit:** `/audit` drives the full cycle; its SKILL.md owns the 7-way partition (Rule 1) and triage. HIGH severity = violations of backtest I1–I12 (`docs/BACKTEST_SPEC.md`), limit post-only, the 2s REST floor, the 15% breaker, Wilder RSI/ATR, or `HYDRA_COMPANION_LIVE_EXECUTION` default-off. Two-phase audit: after fixing HIGH/MED, re-run the partition sweep against your diff, then full tests + `harness.py --mode mock`; done only when phase 2 is clean.

## Windows / WSL gotchas

- **Use Bash (Git Bash) for all shell commands, including in subagents and parallel workers** — PowerShell's cp1252 encoding, quoting differences and inconsistent Python-tooling behaviour break things here. Use PowerShell only when a command explicitly needs it (e.g. registry access).
- Use UTF-8 explicitly — cp1252 crashes on Unicode (the dashboard regime emoji and the console portfolio block both do).
- Time intervals with `time.monotonic()` (what `BaseStream` uses for heartbeats and `RESTART_COOLDOWN_S`) or `time.perf_counter()` — never `time.time()`, whose clock jumps and ~15ms Windows resolution miscount them.
- Escape parentheses inside `.bat` if-blocks — the cmd parser silently drops branches otherwise.
- If the WSL distro is `Ubuntu-22.04` rather than `Ubuntu`, `kraken` calls silently route nowhere — check `wsl -l -v`; fix with `HYDRA_WSL_DISTRO=Ubuntu-22.04`.
